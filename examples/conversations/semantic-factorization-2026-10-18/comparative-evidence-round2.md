# Comparative representation-framework analysis — primary-source expansion, 2026-10-18

**Status:** bounded primary-source desk comparison, **not** a completed systematic literature review, a native-tool conformance evaluation, or a finding that a new canonical factorization is required.

**Research order:** existing frameworks and native/encoded/delegated capabilities → explicit five-scenario judgments → tool-level checks and cross-system contracts → *only then* revisit a purported canonical/MECE representation factorization.

**Provenance:** expands `comparison-matrix.md`, `scenario-evaluation.md`, and provisional requirements R01–R18 in `research-protocol.md`. New judgments and recommendations below are **researcher interpretations**, not claims made verbatim by the standards organizations. Primary materials checked on 2026-10-18. Existing Python fixture oracles, Lean arithmetic proofs, and Z3 toy mapping checks remain separate **post-export** evidence and do not establish DOL/MMT/SysML/Modelica/Maude/TLA+ conformance.

## 1. Method and boundary of the search

The first desk evaluation considered DOL, MMT, institution theory, SysML v2/KerML, Modelica/FMI, ologs, OWL/SKOS/SOSA/SSN/PROV-O and OAEI. This pass **actively tests the possibility that that selection missed a stronger prior-art answer**: an executable general formalism (Maude), a heterogeneous proof/translation *implementation* (Hets), a temporal state-machine formalism (TLA+), a logic interchange standard (Common Logic), and a data-validation standard (SHACL).

Search families inspected: (1) heterogeneous OMS / logic translation / institution / CASL / Hets; (2) modular formal theory representation / MMT; (3) rewriting logic / executable specifications / Maude; (4) temporal actions / state exploration / TLC; (5) dynamic system modeling / Modelica / FMI / SysML; (6) ontology concepts vs constraints / SKOS / OWL / SHACL; (7) observations / SSN / SOSA / provenance / PROV-O; (8) Common Logic / ologs. The materials below are mostly normative standards and official project papers/manuals. This is **targeted expansion with citation checking**, not a database-wide search with a PRISMA-style inclusion count, citation saturation, reproducible paper-level exclusions or quality scoring. All new tools' results are still *documented* rather than *run on the fixtures*.

**Judgment legend:**
- **N** — the obligation is native to the defined formalism/standard or documented tool, **but not necessarily executed here**.
- **E** — expressible using a particular encoding/extension, not native as the scenario's full operation.
- **D** — delegated to a distinct prover, solver, simulator, validation or integration component.
- **O** — outside the framework's stated scope/main operation. This is **not a proof of impossibility**.
- **U** — source evidence insufficient for a substantive judgment.
- A slash such as `N/D` means **native description/interface, delegated execution/checker**; it does not mean we observed a successful implementation.
- No category here means tested, validated, conformant or scientifically true.

**Critical distinctions:** syntax versus model-theoretic semantics; truth in a model versus formally checked proof; description of a transition versus production of a trace; a record of observations versus scientific warrant; alignment suggestion versus semantics-preserving translation; modeling formal semantics versus an actual deployed conformance checker.

### A. Physical theory → simulator → comparison with observations (R05–R08, R10–R11, R14–R16)

- **Documented native:** Modelica specifies the oscillator as a first-order ODE/DAE system and initial conditions; FMI provides *interfaces* for importing/exporting the model. A concrete Modelica simulator is necessary to produce numeric traces. FMI's Model Exchange explicitly delegates the numerical solver to the importer; Co-Simulation wraps separately executed subsystems. [Modelica](https://specification.modelica.org/maint/3.7/MLS.html), [FMI](https://fmi-standard.org/docs/main/).
- **Encoded/delegated:** SysML describes the system's behavior and structures but still needs suitable execution semantics and tooling; MMT/DOL may express or link the mathematical theory but don't numerically integrate it. Maude/TLA+ could approximate a **discretized** oscillator, which changes the verification question. Those approximations should not be scored as native continuous-ODE support. [SysML](https://www.omg.org/sysml/SysML-2.htm), [Maude](https://maude.cs.illinois.edu/overview), [TLA+](https://github.com/tlaplus/tlaplus).
- **Grounding:** SOSA/SSN describes measurement and procedure; PROV-O records provenance. Neither makes a fabricated observation genuine. Required *external* empirical contract: sample identifiers, unit conversions, instrument calibration, uncertainty model, residual criterion and traceable data provenance. [SSN](https://www.w3.org/TR/vocab-ssn-2017/), [PROV-O](https://www.w3.org/TR/prov-o/).
- **Unverified tool check:** compile/run `der(x)=v; der(v)=-x`, `x(0)=1, v(0)=0`; save solver settings, FMI export, results at `0, π/2, π`, numerical tolerances and observable/measurement linkage. Current standalone RK4 oracle is **not** a Modelica/FMI conformance result.

### B. Mathematical theory → theorem → checked proof (R05–R06, R09, R13–R15, R17)

- **Documented native:** MMT can *represent* theories, proof/declaration structures and theory morphisms independently of a fixed foundation. A proof assistant supplies the trusted calculus/checker; MMT's foundation independence should not be mislabeled as an automatic proof service. The prior standalone Lean check of `n + 0 = n` was a real proof-assistant check but not an MMT-native formalization. [MMT language](https://uniformal.github.io/doc/language/), [independence](https://uniformal.github.io/doc/philosophy/independence).
- **Documented implementation competitor:** Hets is an actual heterogeneous proof-management/logic-translation system with integrated external provers; this is a closer operational benchmark than citing institution theory alone. Institution theory contributes the `Sign / Sen / Mod / satisfaction` semantics rather than a checked proof object. [Hets](https://github.com/spechub/Hets), [institution theory](https://iep.utm.edu/insti-th/).
- **Interesting overlap:** Maude represents equations, rewriting deductions and proofs about reachable behavior. Common Logic explicitly excludes prescribing proof theory from its standard. Ologs describe primitive-recursive functions but do not thereby supply arbitrary checked theorems. [Maude manual](https://maude.cs.illinois.edu/manual/), [Common Logic scope](https://webstore.iec.ch/en/publication/63569), [Ologs](https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0024274).
- **Unverified tool check:** formalize the Nat theorem and an explicit theory morphism in MMT; inspect what its checker/foundation verifies. In parallel, have Hets prove or discharge an equivalent CASL conjecture, recording the actual back-end prover and proof status. Preserve *theorem*, *proof term*, *trusted checker*, *metatheoretic assumptions* as distinct records.

### C. Cellular automaton → formal rule → execution/verification (R02, R04, R09–R11, R14–R15)

- **Strongest newly verified prior art:** Maude models states with terms and transitions with rewrite rules and supports rewriting/search and model-checking workflows. It is therefore a **native candidate** for Rule 30 execution and state reachability, not a mere encoding of a mathematical theory awaiting a separate simulator. [Maude manual](https://maude.cs.illinois.edu/manual/), [official overview](https://maude.cs.illinois.edu/overview).
- **Independent native competitor:** TLA+ expresses state-transition/action relations; TLC searches the finite reachable state space and can output traces. A finite 15-cell ring is particularly appropriate, but successful bounded-state exploration says nothing about infinite cell lattices unless separately proved. [TLA+ tools](https://github.com/tlaplus/tlaplus), [TLC usage](https://github.com/tlaplus/tlaplus/blob/master/USE.md).
- **Encoded/delegated competitors:** Modelica can express discrete events, but a synchronous neighborhood update must be carefully encoded; SysML behavioral constructs similarly require an explicit lattice/schedule and execution tool. MMT can encode the rule mathematically; its formal theory is not automatically executable. FMI exchanges executable units but is not itself the cellular automaton language. [Modelica](https://specification.modelica.org/maint/3.7/MLS.html), [SysML](https://www.omg.org/sysml/SysML-2.htm), [MMT](https://uniformal.github.io/doc/language/).
- **Unverified native check:** run the *same* 15-cell, periodic-boundary, synchronous Rule 30 initial condition for six states in **Maude** and **TLC**, compare their traces to the existing oracle, and check the all-zero fixed point. The crucial semantic comparison is whether each step means **simultaneous** update versus sequential local rewriting; document the encoding and transition relation explicitly.

### D. Taxonomy → observation → classification decision (R01–R08, R13–R16)

- **Native but non-identical representations:** SKOS concept hierarchy, OWL domain axioms, and SHACL validation are **three different contracts**. `skos:broader` is not itself subclass entailment. OWL cardinality axioms live under open-world model theory; SHACL validates a supplied RDF data graph against shape constraints and returns a report. [SKOS](https://www.w3.org/TR/skos-reference/), [OWL 2](https://www.w3.org/TR/owl-syntax/), [SHACL](https://www.w3.org/TR/shacl/).
- **Observation/provenance:** SOSA/SSN supports sensors, observations, properties/results and samples; PROV-O supports entities, activities and agents. In a specimen classifier, the *scientific evidence rule* mapping measured features to a taxon is still an application-level assumption to be justified. [SSN 2017 REC](https://www.w3.org/TR/vocab-ssn-2017/), [PROV-O](https://www.w3.org/TR/prov-o/).
- **Important version precision:** As of October 18, 2026, the 'SSN 2023 Edition' is a Working Draft **dated October 12, 2026**, which adds richer observation/execution descriptions and alignment modules. Do not cite new draft vocabulary as an already approved W3C Recommendation. [W3C WD](https://www.w3.org/TR/vocab-ssn-2023/).
- **Unverified check:** define one taxonomy and specimen, two independent observations (including a conflicting/uncertain one), OWL classification claims, SHACL data-quality constraints and a PROV activity linking the decision to the observations. Validate shape failures and corrections. Check separately whether the *substantive classification* is warranted; SHACL conformance alone cannot establish that.

### E. Formalism A → formalism B with semantic-preservation obligation (R05–R06, R12–R15, R17)

- **Native strongest candidates:** DOL expresses networks and mappings of heterogeneous formal OMS. Hets implements parsing, selected cross-logic translations and proof management; MMT explicitly represents theory morphisms and compositions. Institution theory states the abstract preservation law on signatures/sentences/models. [DOL](https://www.omg.org/dol/), [Hets](https://github.com/spechub/Hets), [MMT](https://uniformal.github.io/doc/language/modules), [institution theory](https://iep.utm.edu/insti-th/).
- **Exact semantic obligation (abstract):** for a signature morphism `σ: Σ → Σ′`, source sentence `φ`, and target model `M′`, the institution satisfaction condition has the form `M′ ⊨ Sen(σ)(φ)` if and only if `Mod(σ)(M′) ⊨ φ`. This is an **abstract theorem obligation under the mapped logics**, not evidence that a proposed Person/Human mapping meets it. [Institution theory](https://iep.utm.edu/insti-th/).
- **Boundary tests:** Common Logic 2018 offers semantics-preserving interchange *between dialects of its declared logic family*, not arbitrary formal languages; FMI's 'model exchange' means dynamic-model interface exchange, not universal semantic-preservation proof; SKOS matches can propose alignments without proving logical consequence preservation. [Common Logic](https://webstore.iec.ch/en/publication/63569), [FMI](https://fmi-standard.org/docs/main/), [SKOS](https://www.w3.org/TR/skos-reference/).
- **Unverified check:** a source CASL/OWL or Common Logic formalization declares `Person.ageYears : Integer` and `ageYears ≥ 0`; the target translates to `Human.ageYears` preserving the same constraint. Use Hets and/or DOL with an explicit mapping, invoke actual supported backend checks, and test a *negative control* using age in **days** substituted for years or reversed upper/lower cardinality. Record what the translator and prover actually established. A hand-coded Python value-preservation test or Lean theorem about integers is **not** a tested DOL or Hets translation.

## 5. What this changes from the earlier analysis

1. **Replace 'the formal side needs MMT/DOL; the executable side needs Modelica' as an implied dichotomy.** Maude is serious existing prior art simultaneously for syntax, types, formal deduction, state transition *and execution* within a rewriting-logic family. TLA+/TLC provides another native route for abstract state dynamics. This broadens the chance that already-existing technologies cover an operational ontology.
2. **Treat Hets as the highest-priority executable foil for the DOL/institution-theory hypothesis.** We should not claim a heterogeneous-mapping implementation gap before trying the system that already integrates multiple logics, logical translations and prover management.
3. **Add SHACL to empirical-taxonomy evaluation.** Ontology/cardinality semantics and concrete dataset constraint checking are separate: OWL alone should not be implicitly scored as a complete record validation suite.
4. **Treat Common Logic 2018's explicit exclusions as a useful falsifier.** Broad language expressiveness still does not subsume every proof method, external translation and empirical reference.
5. **Keep MMT and ologs on the serious candidate list**: MMT is more than an ontology vocabulary; ologs are more than passive category trees. Neither's expressive theory paper proves empirical or operational conformance for our fixtures.

## 6. Next falsification tests, in decision order

| Priority | Falsifiable hypothesis | Work product required | Failure/counterexample |
|---|---|---|---|
| **1** | Hets/DOL can relate two supported OMS and discharge a declared age-field invariant across the mapping | Input OMS in supported languages, mapping, versioned Hets/DOL invocation, actual prover output and a wrong-units negative control | 'Successfully parsed' mistaken for proved preservation; loss of units not detected |
| **2** | Maude and TLC can each represent the *same* synchronous Rule 30 transition semantics | Two native models, versioned six-state traces, all-zero fixed-point check, exact shared transition specification | Sequential local rewrite differs from synchronous global step; bound/formal semantics mismatch |
| **3** | Modelica/FMI can run the normalized oscillator and exchange its state/outputs without changing the interpretation of the variables | Modelica source, solver settings, versioned FMU, imported trace, comparison to analytic oracle, unit/initialization metadata | Correct equations but inconsistent initialization, FMI interface loss, or numerical tolerance failure |
| **4** | SKOS/OWL/SHACL/SOSA/PROV separates classification vocabularies, observation evidence, record validity and decision provenance | Example RDF dataset, constraints, validation reports, observations and revised/conflicting classification decision | RDF graph conforms but classification is unsupported; hierarchy conflates SKOS broader and OWL subclass |
| **5** | MMT can formally represent a theorem and a mapping and hand off trusted checking with declared assumptions | MMT theory/morphism, proof artifact, exact checker/foundation configuration | Symbol translation parses but the proof obligation is not discharged |

The order is based on likely information gain, **not** a claim that the later tests are unimportant. Each requires separate status: `documented / encoded / delegated / tool-executed / soundness-assessed / empirically validated`. Do not upgrade a source claim to tool-verified because a nearby synthetic Python, Lean or SMT fixture passed.

## 7. Current synthesis — *not* a canonical factorization

It is possible that the target is **not a new object language** but a system for composing existing artifacts with explicit preservation, execution, evidential and provenance contracts. The comparators suggest several different senses of 'representation': conceptual scheme, formal interpreted language, semantic translation, transition/execution semantics, computational trace, and real-world measurement/warrant. They need not be mutually exclusive.

**Supported conclusion:** strong prior art covers the *individual* obligations across five cases, and Maude/Hets/SHACL/TLA+/Common Logic significantly widen earlier coverage. No reviewed source yet establishes a universal/minimal/MECE decomposition or the correctness of the full cross-framework composition. We cannot claim a novelty gap until actual cross-system tests and deeper citation chaining fail to recover an existing solution.

**Evidence tier of this document:** original primary documentation/specifications and researcher-composed test obligations. **No newly executed Maude, Hets, Modelica, SysML, DOL, MMT or TLA+ test in this round.**
