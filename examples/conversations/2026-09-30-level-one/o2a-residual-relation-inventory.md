# O2A residual relation inventory after donor-remap tests

## Scope

Inventory the locally declared O2A relation types after two semantic deletion tests:

1. Email-Eu-core descriptive/intervention fixture;
2. reflective mutation-policy observation→decision→action→effect→feedback fixture.

The question is not whether a relation name appeared in a fixture. The question is whether a task-relevant capability remains that mature donor frameworks do not already own.

## Inventory

The O2A vocabulary declares 17 local relation types.

### Case-earned core already pressure-tested

| Relation | Status after remaps |
|---|---|
| ProjectionRelation | donor-owned as provenance derivation + representation/mapping profile; retain loss/preservation metadata only |
| TransformationRelation | donor-owned as provenance activity + native transformation/change certificate |
| LicenseRelation | strongly overlaps Assurance 2.0 evidence incorporation/substitution + SACM inference/context |
| LicenseConditionRelation | donor-owned as evidence/premises/assumptions/defeaters/needsSupport |
| ObservationRelation | donor-owned by PROV/EVI plus observation-domain annotations |
| BeliefStateRelation | not needed as universal relation in tested cases; assurance/claim standing + provenance suffices unless a future agent-state consumer requires explicit belief state |
| DecisionRelation | donor-owned by practical reasoning/decision frameworks prospectively and decision provenance retrospectively |
| EffectRelation | donor-owned as subsequent observation/computation/evidence linked to prior action/activity |
| FeedbackRelation | epistemic semantics donor-owned by EVI challenges/assurance defeaters plus provenance/version history; presentation labels can remain local |

None of these has survived the tested cases as a required universal O2A ontology primitive.

### Seam relations

| Relation | Existing owner / interpretation | Recommendation |

### Declared, not case-earned

|---|---|---|

These should not receive another fixture merely to earn O2A vocabulary. Start from the mature owner when a real policy case needs them.

## Roles that still deserve attention

Some roles encode distinctions worth preserving even if their containing O2A relation is deleted:

- analysisStatus: succeeded / failed / partial / not-executed;
- projection loss/invertibility/co-reference;
- transformation preserved/aggregated/approximated/omitted/created/destroyed/conformance;
- claim reach;
- condition state such as unassessed versus unsatisfied;
- precommitment of criteria;
- sought versus achieved consequence class;
- world-model version/correspondence;
- observation reactivity;
- action authority/affordance where execution is real.

The correct question for each is now:

> Which donor standard/profile already represents this distinction, and what preservation strength do we have for the mapping?

Do not retain the containing O2A relation merely to keep one useful field.

## Remaining potentially difficult distinctions

Three areas merit targeted prior-art/adoption work when a real case demands them:

1. **stakes / proof-standard policy** — how declared consequence/risk posture selects an evidentiary or proof standard;
2. **reactive/strategic observation** — when subjects/systems respond to observation, measurement or policy;
3. **authorization versus analytical recommendation versus execution** — especially for automated policy action.

All three are mature research areas. They are not currently evidence for O2A primitives.

## Decision

No additional O2A fixture remap is justified now.

The two remaps have done their job: they show that the core record-side loop and the hard reflective action/feedback case can be represented through mature donors to the declared observable contracts.

The remaining inventory is mostly seams, profiles and agent/decision constructs with obvious mature owners.

## Recommended repository posture

Observation-to-Action should be treated as:

- a valuable research/provenance artifact;
- a donor of real fixtures and semantic requirements;
- a cross-standard integration map;
- potentially a conformance/benchmark corpus;

not, absent contrary evidence, as a new universal observation-to-action ontology.

Do not delete history. Do not immediately refactor the repository. Record this as the current research conclusion and let the next real end-to-end policy-analysis case reveal whether any local join is actually required.
